01 / CONTEXT

Introduction

A panorama requires a shared geometric frame and a rule for combining overlapping samples. This implementation estimates planar homographies from manual correspondences, inverse-warps each view, and blends valid samples with distance-based feather weights. Cylindrical projection provides the additional CS 280A mapping.

The methods below are implemented and covered by deterministic synthetic tests. All photographic experiments remain pending. No photographs, measured point pairs, image-specific matrices, photographic timings, or experimental observations are supplied in this report yet.

Coordinates are (x = column, y = row), with the top-left pixel center at (0, 0). Image-to-image matrices act on column vectors. The photo loader applies EXIF orientation before measurements are interpreted, converts to RGB float64 in [0, 1], and does not resize or modify originals. PNG results are rounded to 8-bit previews; NPZ files retain floating-point images, masks, and origins.

Reading this report. Equations describe the implemented methods. Numbered figure slots identify evidence still to be collected; they are not generated results.

02 / INPUTS

A.1 · Image acquisition

The planned capture procedure is to rotate the camera around a fixed optical center while maintaining substantial overlap between adjacent views. Translation introduces parallax: points at different depths then move by different amounts, which a single homography generally cannot align. A planar subject is another setting where projective alignment is appropriate.

Capture at least two overlapping projective image sets, with enough views for the three mosaic demonstrations. Avoid moving subjects and nearby occluders; keep focus, exposure, white balance, and illumination as consistent as practical. Record the actual camera conditions, view order, overlap, and any unavoidable camera translation after capture. Do not infer camera settings from absent metadata.

03 / GEOMETRY

A.2 · Homography recovery

For a measured source point (x, y) and its destination match (u, v), homogeneous coordinates express the projective mapping up to a nonzero scale. computeH(im1_pts, im2_pts) maps image 1 to image 2. Its scale convention fixes h33 = 1, leaving eight unknowns:

(1) Homogeneous mapping

[u, v, 1]ᵀ ∼ H [x, y, 1]ᵀ
    [ h11  h12  h13 ]
H = [ h21  h22  h23 ]
    [ h31  h32   1  ]

Dividing by the homogeneous denominator gives u = (h11x + h12y + h13)/(h31x + h32y + 1), and the analogous expression for v using the second row. Rearranging supplies two independent rows per correspondence:

(2) Explicit linear system

h = [h11, h12, h13, h21, h22, h23, h31, h32]ᵀ
A[2i]   = [x, y, 1, 0, 0, 0, -u*x, -u*y]
A[2i+1] = [0, 0, 0, x, y, 1, -v*x, -v*y]
b[2i] = u;  b[2i+1] = v
A h = b,  A ∈ ℝ^(2N×8),  b ∈ ℝ^(2N)
ĥ = arg min_h ‖A h - b‖₂²

Both input arrays must be finite real arrays of shape (N, 2), with matching shapes and N ≥ 4. build_homography_system exposes A and b. All cases use float64 numpy.linalg.lstsq(A, b, rcond=None); with more than four pairs this fits an overdetermined system. The solution is reshaped into H with H[2, 2] = 1.

The implementation rejects an equation-system rank below eight, nonfinite coefficients, or a numerically singular H. Collinear or repeated points can be degenerate. The solve minimizes algebraic residual, not reprojection error; coordinates are not normalized, so large or poorly scaled coordinates may fail the numerical rank test. Fixing h33 excludes homographies whose h33 is zero. There is no outlier rejection or RANSAC.

05 / SAMPLING

A.3 · Inverse image warping

Forward mapping can skip destination pixels when transformed source centers do not land on every output center. Inverse warping visits every destination center and computes its source location, avoiding those forward-splatting holes wherever the inverse lies within source support. It does not create content outside the photographed region.

(3) Destination-to-source sampling

[a, b, c]ᵀ = H⁻¹ [x_d, y_d, 1]ᵀ
s_x = a/c;  s_y = b/c
x_d = xmin + column;  y_d = ymin + row

Both warpImageNearestNeighbor and warpImageBilinear return (float64 image, boolean valid mask, (xmin, ymin)). They accept grayscale or RGB data without intensity rescaling. The mask is true only for finite inverse coordinates in the closed source-center rectangle [0, width−1] × [0, height−1], allowing a 10−9 pixel roundoff tolerance. Accepted boundary roundoff is clamped; other outside samples remain zero and invalid.

Nearest neighbor reads the source at (floor(sx + 0.5), floor(sy + 0.5)); half-pixel ties go toward positive infinity. Bilinear interpolation uses fractional distances from floor coordinates and combines four values manually:

(4) Four-neighbor interpolation

x0 = floor(s_x);  y0 = floor(s_y)
x1 = min(x0+1, width-1); y1 = min(y0+1, height-1)
α = s_x-x0;  β = s_y-y0
I_d = (1-α)(1-β) I[y0,x0] + α(1-β) I[y0,x1]
    + (1-α)β I[y1,x0]     + αβ I[y1,x1]

At exact last-row or last-column samples, repeating the edge neighbor preserves its value without darkening. Nearest neighbor preserves a selected sample but can produce visible steps under magnification. Bilinear interpolates intensity changes and can soften detail; it performs more sample reads and arithmetic. Neither method supplies an area-based antialiasing filter for strong minification. No measured photographic quality or speed advantage is claimed yet.

The output box encloses the four transformed source pixel-center corners. Its minima are floored and maxima ceiled, inclusively: width = xmax−xmin+1 and height = ymax−ymin+1. Near-integer corner roundoff is snapped within 10−9. Negative coordinates remain in the returned origin. The rectangle can contain invalid pixels around the transformed footprint. A singular transform or a projective horizon touching/crossing the source is rejected. Inverse grids are processed in blocks of up to 128 rows.

07 / COMPOSITION

A.4 · Planar mosaics & feather blending

Select a reference image with identity transform. compose_to_reference chains adjacent source-to-destination matrices or their inverses into that frame. With column vectors, order matters: Hac = Hbc Hab, with the rightmost mapping applied first. Composed matrices are checked for finite values and numerical rank; h33 is not renormalized after composition.

create_panorama computes each transformed corner box, takes their union, and places the existing bilinear warps and masks at exact integer offsets on one shared canvas. The returned origin carries the reference coordinates of its top-left sample. All images must share grayscale or RGB channel layout; dimensions may differ.

(5) Mask-aware feather weights

d_i(p) = distance to nearest invalid mask pixel
w_i(p) = d_i(p) / Σ_j d_j(p), when Σ_j d_j(p) > 0
I_out(p) = Σ_i w_i(p) I_i(p)
M_union(p) = [Σ_j d_j(p) > 0]

A SciPy Euclidean distance transform measures distance within each valid mask, with a one-pixel invalid ring padded outside the canvas so valid edge pixels still receive positive weights. Weights are zero outside a mask and sum to one on the union. A single contributor preserves its value; overlap is a convex weighted average. Where there is no contributor, the image and weights remain zero and the mask is false.

Validity depends on masks, not whether RGB values are nonzero, so true black pixels contribute correctly. Gradual weights reduce abrupt boundary transitions. They cannot correct misregistered edges, parallax, moving objects, or exposure differences; overlap may still show ghosts or seams. There is no exposure compensation or multiband blending.

08 / CS 280A EXTENSION

A.5 · Cylindrical projection

cylindrical_warp requires a positive finite focal length f measured in pixels. It assumes a centered principal point cx = (width−1)/2 and cy = (height−1)/2, without estimating calibration. The centered cylindrical grid uses these forward and inverse equations:

(6) Forward cylindrical coordinates

u = f atan((x-c_x)/f)
v = f (y-c_y) / √((x-c_x)² + f²)

(7) Inverse cylindrical sampling

θ = u/f;  |θ| < π/2
x = f tan(θ) + c_x
y = v/cos(θ) + c_y

The code evaluates the forward map with atan2 and hypot. Horizontal extrema come from the side edges; vertical extrema occur on x = cx, so transforming only four corners would miss part of the curved region. Inclusive integer bounds enclose that region. Output [row, column] has coordinates (umin+column, vmin+row).

For each valid inverse sample, the shared manual bilinear helper samples the original image directly. The workflow projects each original once, then places the projection and mask without a second interpolation pass. Invalid regions are zero with mask false, using the same finite-source and roundoff conventions as planar warping. There is no angular wrapping.

(8) Supported cylindrical alignment

u_reference = u_local + offset_i
For equal f and pure yaw: offset_i = f × yaw_i
The workflow accepts integer-pixel horizontal offsets only.

A cylindrical surface can represent a wider horizontal field of view without projecting all views onto one tangent plane, but it still assumes suitable camera motion and calibration. The pure-yaw relation uses radians and a chosen consistent reference direction. Arbitrary planar homographies cannot be reused unchanged after projection. The current CLI requires supplied integer offsets; it does not estimate alignment, support fractional shifts, or model pitch, roll, camera translation, or lens distortion.

With even source dimensions, the principal point is half-integer while the cylindrical output grid is centered on integers. Consequently a very large f does not generally reproduce the original pixel lattice exactly. Very small f may leave only a narrow sampled region. These are sampling/model limitations rather than evidence from a photograph.

09 / SCOPE

Numerical & practical limitations

The homography is a global projective model; there is no automatic matching, robust fitting, or geometric refinement. Manual matches and corner semantics need review. A mask records sampling support, not a semantic foreground. Bilinear interpolation cannot recover absent detail and is not a full minification filter.

Canvases above 25 million pixels are rejected. Panorama arrays also have an estimated 512 MiB budget for retained layers, masks, weights, output, and distance workspace. Cylindrical output has a separate 512 MiB estimate including its source copy. Neither estimate bounds process RSS: source conversions can happen before the check, projected views are retained, and row-block temporaries and caller-owned images consume additional memory. A planar RGB float64 output alone at the pixel cap uses 600 MB before its mask and temporary arrays.

Photo configuration templates are intentionally incomplete and fail before any fallback processing. Completed runs require a new output directory; a disk-write failure may leave a partial new directory for inspection. Original-image hashes and measured parameters are recorded in metadata. No existing input image is rewritten.

10 / DISCUSSION

Validation & supported conclusions

The local tests independently reproject synthetic correspondences and check known identity, translation, affine, perspective, overdetermined, and noisy cases. Warping tests check analytical pixel values, origins, masks, exact edges, negative coordinates, and invalid transforms for grayscale and RGB arrays. Integration tests check noncommuting transform composition, shared-canvas placement, feather weights, cylindrical camera-ray geometry, and single-pass sampling.

These checks support the implementation's coordinate conventions and behavior on their deterministic synthetic inputs. They do not establish alignment quality, visual quality, or performance on photographs. No synthetic benchmark timing, photographic matrix, or invented result is reported here. Core numerical operations use NumPy; Pillow decodes local images, Matplotlib renders figures, and SciPy supplies only the feather-weight distance transform.

Conclusions from the implemented methods

Inverse sampling makes output support explicit through a mask and origin. Feathering combines valid aligned samples without treating black as missing data, while geometric accuracy remains the responsibility of the estimated transforms. Cylindrical projection changes the alignment coordinate frame and therefore requires its own supported alignment model. Photographic conclusions must wait for measured experiments.
